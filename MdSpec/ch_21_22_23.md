# Shortest Paths

## SPT 算法的引入

在边没有权重的条件下，BFS能给出正确的答案（每条边权重为1，最短路径=边数最少的路径。BFS能给出边数最少的路径，此时它是正确的）。 
但在加权图上就不一样了。加权图最短路径可以有非常多的边，只要这条路上的所有边权加和最小就行。此时BFS就有些不太适用了。

There are many algorithms for shortest paths.
One common approach: Start from an incorrect SPT -> Make improvements until your SPT is correct.

Common improvement operation: `Edge Relaxation` and `Node Relaxation`.
- relax(E) definition: If edge E is better, use it instead.
- relax(v) definition: Relax all of v’s outgoing edges.

There are many valid SPT algorithms that use relaxation.Example Algorithm:
- `Bellman-Ford` (1955): Relax all edges (in any order), repeat V times.
- `Dijkstra’s Algorithm` (1956): Relax all nodes exactly once in “closest first” order.
- `The Duan-Mao et. al Algorithm` (2025): Relax edges in batches.

这时，就引入了另一个算法 —— `Dijkstra`。

## Dijkstra 算法

`Dijkstra’s Algorithm`: Visit the vertices in `Closest First order`, building the SPT as you go.

`Dijkstra Algorithm的算法思路/伪代码`：
- Insert all vertices into fringe PQ, storing vertices in order of distance from source.
- Repeat: Remove (closest) vertex v from PQ, and relax all edges pointing from v.
```
Pseudocode below:
  add all vertices to PQ with infinite priority
  while (!pq.isEmpty()) {
      v = pq.removeMin();
      relax(v); // i.e. relax all edges from v
  }

Dijkstra 伪代码：
  建一个 PQ
  把源点 s 放进去，优先级 0；其余所有点放进去，优先级 ∞
  当 PQ 非空：
      p = 取出优先级最小的
      松弛 p 的所有出边
```
Dijkstra的fringe不再是队列，而是一个按disTo排好序的优先队列（PQ）。
distTo[idx]数组代表idx对应节点到source/起点的距离（权重和）。
edgeTo[]每个元素为索引对应节点的前置节点（edgeTo[2] = A，代表索引2对应的节点C的前置节点为A，即 A->C 边）。

In Dijkstra’s algorithm, relaxing a magenta arrow pointing to a white (already visited) node NEVER works. Why? By example in lecture:
- We already visited C!
- That means C is closer than E.
- So impossible for E→C to be better.

`Dijkstra算法成立的原因`在于：Once a vertex is popped off the priority queue, it is never re-added. Its distance is never re-updated. So, in other words, once a vertex is popped from the priority queue, we know the true shortest distance to that vertex from the source.

Dijkstra算法的PQ在弹出一个元素时，从源点到该元素的最短路径就已经确定了。所以，有时候可以多接受一个参数——目标元素（`short-circuiting`）。例如：全世界城市连通当图，求 Berkeley 到 Oakland 的最短路。跑 Dijkstra(Berkeley) 意味着这个算法会一路算到 LA、Houston、纽约——全部算完才停。事实上只要 Oakland 一被弹出，立刻可以返回，结果一定正确。

`Dijkstra算法的缺陷`——负权图： Dijkstra's algorithm is not guaranteed to be correct for negative edges. It might work... but it isn't guaranteed to work.

`Dijkstra算法的改进`——有方向感的`A*`算法: 还是之前刚提到的例子 Berkeley→Oakland 那个场景。短路能省时间，但它只在你运气好、目标很快被弹出时才节省。

它就像一个水波一样三百六十度转一圈后再扩一点距离，有三百六十度扩散搜索。问题就出在这里——没有方向。一个城市，你知道它在起点大致哪个方向，却在不相关的方向上花费时间寻找路线。这不就是无用功吗？

改进的方式修改PQ的优先级计算公式，增加一个方向相关的因子：PQ的排序按照`distTo(v) + h(v)`大小来定。
```
distTo(v)  +  h(v) // 优先级大小计算公式
   ↑            ↑
已经花了多少   从这里到目标，估计还要多少
```
现在的问题来到了h(v)如何计算。这一启发式怎样算是“好”？两个原则：满足一致性一定可采纳，反之则不然。
- admissibility(可采纳):不需高估。估值可以小但一定不能大于实际值。`h(v, target)  ≤  真实距离(v → target)`
- consistency(一致性):三角形两边之和大于第三边。`h(v)  ≤  weight(v, w) + h(w)`

注意：A* 返回的是“按 h 判断最好的路”，不是“客观最短的路”。

# MST: Minimum Spanning Trees(最小生成树)

## 理论/定义

Given an undirected graph, a `spanning tree` T is a subgraph of G, where T:
- Is connected.
- Is acyclic.
- Includes all of the vertices.

MST Definition:
- A `minimum spanning tree` (`MST`) is the lightest set of edges in a graph possible such that all the vertices are connected. Because it is a tree, it must be connected and acyclic. And it is called "spanning" since all vertices are included.
- A `minimum spanning tree` is a spanning tree of minimum total weight.

“最小”修饰的是整棵树的边权总和，不是任何一条边；MST 的边数永远是 V−1（V 是顶点数）。

`SPT`(shortest path tree): 最短路径树。SPT 是“让每个顶点都离目标点最近”。 MST 是“用最少的权重把所有顶点连起来”，没有目标点（source vertex）。两者都是树，但优化的指标不同。

`Cut Property`:
- cut（割）：We can define a cut as an assignment of a graph's nodes to two non-empty sets (i.e. we assign every node to either set number one or set number two). 把所有顶点分成两堆，每堆不能为空。
- `crossing edge`（横切边）：We can define a crossing edge as an edge which connects a node from one set to a node from the other set. 两段分别落在两堆里的边。两段不得在同一堆。
- `Cut Property`：given any cut, the minimum weight crossing edge is in the MST. 对于任意一个割，任取一条权重最小的横切边，存在一棵MST包含该横切边。

`Generic MST Finding Algorithm`：Prim算法 and Kruskal算法
- It's important to note that the MST returned by Kruskal's might not be the same one returned by Prim's, but both algorithms will always return a MST.

## Prim's Algorithm

`Prim`: By the Cut Property, the added edge is necessarily part of the final MST.
- Start from some arbitrary node.（随便选一个点开始）
- Repeatedly add the shortest edge that has one node inside the MST in construction.（反复加“只有一端已在树里”的最短边及其顶点 ——> 一个割对应的最小横切边）
- Repeat until there are V − 1 edges.（直到 V−1 条边）

Why does Prim’s work? Special case of generic algorithm.
- Suppose we add edge e = v->w.
- Side 1 of cut is all vertices connected to start, side 2 is all the others.
- No crossing edge are in the MST
- No crossing edge has lower weight (considered the edges in increasing weight order).

Prim 与 Dijkstra 的区别（要不要累加？）：distTo[p] + 这个前缀的有无，就是 SPT 和 MST 的分水岭。
- Prim’s and Dijkstra’s algorithms are exactly the same, except Dijkstra’s considers “distance from a single source node”, and Prim’s considers “distance from a tree.”
  - Dijkstra 的 distTo[q] 意思是“从源点走到 q，一路上所有边加起来多少”。 
  - Prim 的 distTo[q] 意思是“从 q 一步跨进树，要花多少”——只算那一条边，跟你怎么走到 p 的无关。
```
Dijkstra 版：
    if distTo[p] + w(p,q) < distTo[q]:
        distTo[q] = distTo[p] + w(p,q)      ← 有 distTo[p] +

Prim 版：
    if w(p,q) < distTo[q]:
        distTo[q] = w(p,q)                  ← 没有 distTo[p] +
```
```java
public class PrimMST {
    public PrimMST(EdgeWeightedGraph G) {
        edgeTo = new Edge[G.V()];
        distTo = new double[G.V()];
        marked = new boolean[G.V()];
        fringe = new SpecialPQ<Double>(G.V());

        distTo[s] = 0.0;
        setDistancesToInfinityExceptS(s);
        insertAllVertices(fringe);

        /* Get vertices in order of distance from tree. */
        while (!fringe.isEmpty()) {
            int v = fringe.delMin();
            scan(G, v);
        }
    }

    private void scan(EdgeWeightedGraph G, int v) {
        marked[v] = true;
        for (Edge e : G.adj(v)) {
            int w = e.other(v);
            if (marked[w]) {
                continue;
            }
            if (e.weight() < distTo[w]) {
                distTo[w] = e.weight();
                edgeTo[w] = e;
                pq.decreasePriority(w, distTo[w]);
            }
        }
    }
}
```

## Kruskal's Algorithm

`Kruskal's Algorithm`算法思路: fringe——排序PQ+并查集（如WQU）
- Sort all the edges from lightest to heaviest.（所有边从小到大排序 ——> 需要排序 -> PQ）
- Taking one edge at a time (in sorted order), add it to the MST under construction if doing so does not introduce a cycle.（依次取边，不成环就加 ——> 每次取当前权重最小的边，同时要判断两端的顶点是否连通 ——> 并查集——当待加入边两个顶点已经在并查集中是连通的，说明待加入边是两个顶点之间的的第二条路径，即有环存在了）
- Repeat until there are V − 1 edges.（直到 V−1 条 ——> 循环停止）

Why does Kruskal’s work? Special case of generic MST algorithm.
- Suppose we add edge e = v->w.
- Side 1 of cut is all vertices connected to v, side 2 is everything else.
- No crossing edge is black (since we don’t allow cycles).
- No crossing edge has lower weight (consider in increasing order).

`Kruskal's Algorithm Pseudocode`:
```java
public class KruskalMST {
  private List<Edge> mst = new ArrayList<Edge>();
 
  public KruskalMST(EdgeWeightedGraph G) {
    MinPQ<Edge> pq = new MinPQ<Edge>();
    for (Edge e : G.edges()) {
      pq.insert(e);
    }
    WeightedQuickUnionPC uf = 
             new WeightedQuickUnionPC(G.V());
    while (!pq.isEmpty() && mst.size() < G.V() - 1) {
      Edge e = pq.delMin();
      int v = e.from();
      int w = e.to();
      if (!uf.connected(v, w)) {
        uf.union(v, w);
        mst.add(e); 
} } } }
```

## Topological Sort Problems

`Topological Sort`(拓扑排序):
- an ordering of a graph's vertices such that for every directed edge u→v, u comes before v in the ordering.
- the topological sort for the DAG has to start with source vertex and must end with sink vertex.
  - source: 入度为零的顶点——没有前置。
  - sink: 出度为零的顶点——没有后继。
  - linearization: 线性化，把图画成一条横线。

拓扑排序做的事，本质上是把一个“偏序”（只知道一部分先后）补成一个“全序”（排成一条线）。补法有很多种。

拓扑排序的前提是：有方向且无环，也就是说有向无环图才行（DAG）。

### DFS post-order+反转 实现拓扑排序

DFS post-order实现拓扑排序算法：restart from every vertex with indegree 0.
- Perform a DFS traversal from every vertex in the graph, not clearing markings in between traversals.
- Record DFS postorder along the way.
- Topological ordering is the reverse of the postorder.

对每个还没标记的点跑一次 DFS；
DFS 过程中记下后序（postorder：递归返回之后才把点加进列表）；
把这个列表反转，就是拓扑序。

为什么DFS后序遍历的结果翻转后得到的是拓扑排序的结果？
- Each vertex v gets added to the end of the postorder list only after considering all descendants of v. 
- Thus, when any v is added to the postorder list, all its descendants are already on the list. 
- Thus reversing this list gives a topological ordering.
- 后序里，“后代”一定排在“祖先”前面。越“深”的点越靠前。
- 反转之后，“祖先”就跑到“后代”前面了。

### BFS实现拓扑排序：Khan算法

Khan算法：
- 算出每个点的入度（有几个前置）
- 找入度为 0 的点，输出它；
- 把它和它的所有出边“删掉”（等价于让邻居的入度减 1）；
- 重复，直到所有点都输出。

Khan算法能够检测环，并且还更为直观（相较于DFS后序）。

## DAG-SPT Problems： 有负权存在的最短路径问题

DAG-SPT能够解决DAG的最短路径问题（生成SPT）。相较于Dijkstra，改变了处理的先后顺序：按照拓扑排序的顺序来处理(Relax in Topological Order)，且没有fringe。Visit vertices in topological order.
- On each visit, relax all outgoing edges.
- Each vertex is visited only when all possible info about it has been used


DAG-SPT要按照拓扑排序的顺序进行处理，这是前提。拓扑顺序来源于DAG这一结构。所以，一定要满足这一前提条件，即不能有环。

对于有负权存在，却又不是DAG的图，则需要用到 Bellman-Ford算法。

## DAG最长路问题

最长路径问题在一般图上解决不了（要不指数级复杂度，要不就无穷大），但是在DAG上可以实现。

算法三步：权重取反 —— 求最短路径 —— 翻转结果
- Form a new copy of the graph, called `G'`, with all edge weights negated (signs flipped). （复制一份图，所有边权取反）
- Run DAG shortest paths on G' yielding result X. （在 G' 上跑 DAG 最短路，得到结果 X）
- Flip the signs of all values in X.distTo. X.edgeTo is already correct. （把 X 的 distTo 全部取反；edgeTo 不用动，它本来就是对的）

取反那个办法让你完全不用改算法内部，只在输入和输出两头动手。相当于新问题来了，你不改算法黑盒，你改输入，再改输出。*这是一种思维方式*。实际工程上不一定会这么做。

## 思维方式：归约与分解（Reduction and Decomposite）

`Reduction`: 
- Formally, if any subroutine for task Q can be used to solve P, we say P reduces to Q.
- 如果 Q 的一个子程序能用来解决 P，就说“P 归约到 Q”。
  - DAG 最短路（DAG-SPT）能解 DAG 最长路（DAG-LPT），所以 DAG-LPT 归约到 DAG-SPT。
  - 归约的方向 = “谁用谁”。P 用了 Q，就是 P → Q。“问题指向工具”，工具在右边。
  - 同一个问题可以归约到很多不同的工具。
- Three steps of Reduction:
  - preprocess（预处理）: 改造输入，使之能被Q利用。
  - solve（求解）:用Q处理改造后的输入。
  - postprocess（后处理）:把Q得到的输出转换成P需要的形式/答案。

归约的例子：3SAT -> 独立集

独立集：一堆顶点，里面任意两个都不相邻（没有边直接连着）。
独立集问题：存不存在一个大小为k的独立集？
3SAT问题：Given a boolean formula, does there exist a truth value for boolean variables that obeys a set of 3-variable disjunctive constraints?（给一个这样的公式，存不存在一组真假赋值让它整体为真？）
解法：
- For each clause in X, create 3 vertices in a triangle.（每个子句对应一个三角形）
- Add an edge between each literal and its negation.（每个文字和它的否定之间连一条边，求：大小为“子句数”的独立集）

`Decomposite`: 任务分解，把复杂任务拆成小块，一块一块解决（靠抽象）。
-  Breaking a complex task into smaller parts. Using abstraction to make problems solving easier. 
- This is the heart of computer science.

分解考验的是“会不会拆”和“接口设计”。归约考验的是“能不能看出两个问题是一回事”——这个更难，也更有迁移价值。
