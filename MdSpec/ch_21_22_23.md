# Shortest Paths

在边没有权重的条件下，BFS能给出正确的答案（每条边权重为1，最短路径=边数最少的路径。BFS能给出边数最少的路径，此时它是正确的）。 
但在加权图上就不一样了。加权图最短路径可以有非常多的边，只要这条路上的所有边权加和最小就行。此时BFS就有些不太适用了。这时，就引入了另一个算法 —— `Dijkstra`。

Dijkstra的fringe不再是队列，而是一个按disTo排好序的优先队列（PQ）。
```
Dijkstra 伪代码：

建一个 PQ
把源点 s 放进去，优先级 0；其余所有点放进去，优先级 ∞
当 PQ 非空：
    p = 取出优先级最小的
    松弛 p 的所有出边
```

Dijkstra算法成立的原因就在于：Once a vertex is popped off the priority queue, it is never re-added. Its distance is never re-updated. So, in other words, once a vertex is popped from the priority queue, we know the true shortest distance to that vertex from the source.

Dijkstra算法的PQ在弹出一个元素时，从源点到该元素的最短路径就已经确定了。所以，有时候可以多接受一个参数——目标元素（`short-circuiting`）。例如：全世界城市当图，求 Berkeley 到 Oakland 的最短路。跑 Dijkstra(Berkeley) 意味着这个算法会一路算到 LA、Houston、纽约——全部算完才停。事实上只要 Oakland 一被弹出，立刻可以返回，结果一定正确。

Dijkstra算法的缺陷——负权图： Dijkstra's algorithm is not guaranteed to be correct for negative edges. It might work... but it isn't guaranteed to work.
