# 哈希表的提出及修补

数组可以直接按照索引一步取值，为什么树不可以呢？
- 树要求元素具有可比性 ——> 引发出：不靠比较定位可否改善？靠什么呢？计算
- 树的时间复杂度为θ(log N) ——> 引发出：怎么降低时间复杂度到常数阶？均摊

哈希（hash）就是从这两条出发，试图解决这一问题。哈希不再要求容器里的元素具有可比性，把时间复杂度降低到常数阶。

## 改进思路/解决方案探索（deriving hash tables）

方案一：数组的索引/下标 = 数据的编号（数据-编号对，存储编号。通过查询编号，还原得到数据本身）
1. 数组的索引就等于该数据本身：容量大，浪费内存；数组的索引是Integer，因此也只能存储整数，不能存储字符串等其他类型；
2. 沿用1的思路，索引等于数据的编号：空间要求大；
3. 用ASCII来编号：编号不够现实中的数据使用

方案二：方案一要求的唯一性很难实现，该换思路：允许碰撞。只要求是个编号/整数，能分辨即可。
1. hashcode()返回一个int（大约正负21亿这个区间内，约四十亿个可能值）；
2. Math.floorMod(key.hashcode(), array.length)：抽屉原理。把这些可能的值放进需要数量的桶中。（一个桶中可能存在多个值，就如抽屉中放许多物品一般。——> 不再保证唯一性，即允许碰撞collision）

For this type of data structure, each list is sometimes called a “bucket”.
- May have any number of items in a bucket.
- An integer lands in a bucket based on the `reduction function`.
  - Modulus is the most natural and best reduction function

A DynamicArrayOfSequences with a finite internalization function is called a `hash table`.
- Data is converted by a `hash function` into a finite integer representation called a `hash code`. Java hash codes must be in [-2,147,483,648 to 2,147,483,647].
- The hash code is then reduced to a `valid index`, usually using the modulus operator, e.g. 2348762878 % 10 = 8.


哈希表的核心就如上述：允许碰撞这一条件带来数组大小可控。`Java的哈希表就是一个链表的数组`
- valid: 哈希表是否合法要满足确定性和一致性
  - Deterministic：相等的数据hashcode的结果也相等。
  - Consistent：同一个数据的hashcode的结果不变。
- good: 合法 + 分布尽量均匀 + 性能好（算得快，理想为θ(1)这类常数阶）
- 哈希表是无序的。

## Hash Tables in Java

`Hash table`s are the most popular implementation for `set`s and `maps`.
- Great performance in practice.
- Doesn’t require items to be comparable.
- Implementations often relatively simple.
- Python dictionaries are just hash tables in disguise.

In Java, implemented as `java.util.HashMap` and `java.util.HashSet`.
- How does a HashMap know how to compute each object’s hash code?
  - Good news: It’s not “implements Hashable”.
  - Instead, all objects in Java must implement a .hashCode() method

Java hash tables:
- Data is converted by the hashCode method an integer representation called a hash code.
- The hash code is then reduced to a valid index, using something like the floorMod function, e.g. Math.floorMod(1732557 % 4) = 8.
- Data is then stored in a bucket corresponding to that index.
- Resize when load factor N/M exceeds some constant.
- If items are spread out nicely, you get Θ(1) average runtime.

## Collision Solution

碰撞会使得多个元素的下标一致，这些元素本应该放在同一个格子中。允许碰撞带来的问题，如何解决？

线性探测（linear probing）：元素本来对应的格子被占用了，就往下搜索，找到空位去存储。
- 查询空位必须一路找下去，直到遇到空位才能停止。
- 删除哈希表中的元素不能直接置空null。要放一个墓碑（tombstone）标记“查找时直接往下，插入时可以直接插入”。
- 性能缺陷（clustering）：格子连成一片，越来越长会降低性能。

外部链式（external chaining）：同一个下标的元素放入同一个容器（例如链表，LinkedList）。这个容器被称为桶（bucket）。
- 以链表为例，插入是在链表头，删除是在链表尾。
- 查找是遍历链表：此时，不再需要tombstone标记。

元素多了，碰撞就会变多。桶必然变大。如何衡量哈希表的负荷程度？桶装的太多/哈希表装满了怎么办？ —— 装载因子（load factor）与扩容（resize）。
- load factor：等价于“一个桶的平均长度”。
- 扩容不只是把容量变大，还要做得是重新计算hashcode值、重新放入桶中。
- 分布均匀且能扩容的哈希表，其均摊的时间复杂度为常数阶。

哈希表合法要保证确定性和一致性。使用默认的hashcode方法，返回的是对象的内存地址。这会导致：两个对象，equals方法的结果是相等的。但是因为地址的不同而返回了不用的哈希值。这违反了合法性的要求。—— 这就要求覆盖了equals方法，就必须一致的覆盖hashcode方法。

如果hashcode方法计算哈希值的过程，依赖可变字段。可变字段的改变，可能会导致同一个元素前后的哈希值结果不一。这无疑也是不合法的。怎么办？
- 优先选用不可变字段（String，Integer）
- 选用可变字段，在使用期间不得发生变化。例如，可用List，但在使用时不能改变具体的对象（如增、删操作）。
- The `final` keyword will help the compiler ensure immutability.
  - final variable means you may assign a value once (either in constructor of class or in initializer), but after it can never change.
  - Final is neither sufficient nor necessary for a class to be immutable.


# Tries

HashMap 已经 Θ(1) 了，还能更快吗？教材的回答是：如果你对数据有额外了解，可以。

特例一：key 只可能是 ASCII 字符（0–127）。 那就别哈希了，直接开 128 格数组，第 c 格存字符 c 的值：
```java
public class DataIndexedCharMap<V> {
    private V[] items;
    public DataIndexedCharMap(int R) { items = (V[]) new Object[R]; }
    public void put(char c, V val) { items[c] = val; }
    public V get(char c) { return items[c]; }
}
```
没有桶、没有碰撞、没有 hashCode——下标就是字符本身。代价：128 格全开，哪怕你只存 3 个键。

特例二：key 是字符串 → Trie（天然按照字母排序）。

假设要存六个词：sam、sad、sap、same、a、awls。可以这样想：
- 每个节点只存一个字母
- 节点可以被多个 key 共享

过程如下：
- 先放 sam、sad
- 加 sap：已经有 sa 这条前缀，从 a 下面再分一支 p
- 加 same：已经有 sam，从 m 下面接 e
- 加 a："a" 是独立的一个词，还是 "ame" 的开头。必须新建一个节点
- 加 awls：复用这个新的 a，往下接 w-l-s

现在冒出一个新的问题：树里 sam 是一条路径，sa 也是一条路径，awl 也是。哪些算"词"？ 答案：给每个词的最后一个字母节点涂蓝（isKey = true）。

查找就是：从根往下走字符。只有两种失败方式——走到头了但节点是白的（sa），或者走到一半掉出树（saq）。

Trie 也能当 map：蓝节点上再存一个值（比如词频）。
